# 船长 App 水果色视觉规范（现行）

> 更新：2026-10-17。保留原文件路径，本文为全 App 唯一现行视觉规范；历史设计方案、审计和案例中的旧数值不再作为新增页面的依据。
>
> 本次采用 Material Design 3 的语义角色、层级、状态与触控规则适配现有 **Java/XML + AppCompat** 工程。没有迁移 Compose，没有升级依赖，也不代表已集成正式 Material 3 组件库。

## 1. 范围与必须保护的行为

适用于首页、我的、语音记事本、二维码与扫码、资源解析与媒体预览、国际象棋页面、计时器外围、网页容器和共享弹层。规范约束视觉及其状态表达，不授权改写页面路由、业务 owner、权限、请求时序、数据校验、存储或分享语义。

必须保留首页两个 Tab、隐藏入口及拖拽排序记录；保留已有二维码、解析、棋类、计时和网页行为。语音长按、取消和确认保存遵循已确认的功能方案，不以“统一样式”为由附加自动分享或改变持久化契约。

棋盘及坐标、二维码像素、媒体内容、计时器水滴和天气画面、内嵌网页属于专用内容；只统一外围操作和可读性。第三方内容不强行套用品牌背景。隐私同意、拒绝及密码输入的授权与安全规则不能因视觉调整改变。

## 2. 资源与复用规则

- 色值唯一来源为 `captain/src/main/res/values/colors.xml`，尺寸为同目录 `dimens.xml`，共享样式为 `styles.xml`。优先复用语义名，不能在功能模块重新复制近似色板。
- `captain_brand_primary` 指向 `captain_brand_700`；`captain_text_on_brand` 指向正文色。已有 `captain_xhs_*` 通用语义保留别名并复用主规范，专用选择遮罩保留自身语义。
- `base` 在 `base/src/main/res/values/attrs.xml` 声明主题角色，在宿主 `AppTheme` 绑定真实 token。共享容器只消费角色，不引用 App 内部业务状态，不另定义水果色。
- 不依靠新增渐变、阴影、发光、装饰图或重复卡片提高“设计感”。先用内容顺序、留白、字号和表面层级表达结构；按钮不能仅靠颜色区分状态。
- 新增 token 必须有现有角色不能表达的稳定语义、真实消费者和明确作用。禁止为了单页审美新增“另一个粉色”。

### 2.1 共享样式

| 用途 | 优先复用 | 行为边界 |
| --- | --- | --- |
| 主操作 | `CaptainButton.Primary` | 品牌粉实心、深色字、最小 48dp |
| 次操作 | `CaptainButton.Secondary` | 浅品牌表面、深品牌字，不叠加装饰描边 |
| 辅助操作 | `CaptainButton.Text` | 系统状态层反馈，仍保留 48dp 触控区 |
| 输入框 | `CaptainInput` | 原生输入能力、16sp、最小 48dp；不改变密码和输入协议 |
| 标题栏 | `CaptainToolbarTitle` | 22sp，由 base 主题属性消费 |
| 标题与正文 | `CaptainText.Hero/PageTitle/CardTitle/Body/Caption` | 按下文字号表选择，不为挤内容降级 |
| 内容表面 | `CaptainCard`、`CaptainCard.Large` | 仅在内容需要分组时使用，不给每段文字套卡片 |

## 4. 排版、形状与尺寸

### 4.1 字号

| 资源 | 值 | 用途 |
| --- | --- | --- |
| `captain_text_hero` / `captain_text_page_title` | 22sp | 欢迎区及页面标题 |
| `captain_text_card_title` | 18sp | 分组标题 |
| `captain_text_body` | 16sp | 正文、输入与按钮 |
| `captain_text_caption` / `captain_text_tab` | 14sp | 辅助信息、底部导航 |

平台默认 TextView 通过 `CaptainNativeTextView` 使用正文 16sp；平台 `textAppearanceLarge`、偏好标题 `textAppearanceListItem/Small` 映射分组 18sp，`textAppearanceMedium` 为正文 16sp，`textAppearanceSmall` 与偏好 summary 的 `textAppearanceListItemSecondary` 为辅助 14sp；显式页面样式和媒体白字继续优先。

字号使用 sp；标题优先现有 `sans-serif-medium` 和系统可用字重，正文保持中文行高。不得通过缩小文字、强制单行或裁切来隐藏窄屏和大字体问题。首页入口允许两行，关键内容完整性仍需运行验证。

### 4.2 形状与触控

| 资源或语义 | 值 | 约束 |
| --- | --- | --- |
| `captain_radius_control` / `captain_radius_button` | 12dp | 普通按钮和控件 |
| `captain_radius_card` / `captain_radius_icon_tile` | 16dp | 内容卡片和图标底板 |
| `captain_radius_container` / `captain_radius_modal` | 28dp | 弹层、大容器；modal 为语义别名 |
| `captain_radius_card_large` / `captain_radius_tab_shell` | 指向 container | 兼容已有消费者，不新增相近档 |
| 头像、胶囊、波形、棋盘和自绘内容 | 既有专用值 | 不机械替换为普通卡片形状 |
| `captain_size_button_height` | 最小 48dp | 高度内容驱动；长文案允许增高 |
| 语音长按输入 | 最小 64dp | 录音/取消/确认有明确状态 |
| `captain_size_list_item_height` | 最小 56dp | 不压缩文字换取密度 |

底部导航当前使用 base 的 `captain_size_bottom_bar_height=56dp`，由主壳层避让系统底部 inset；`captain_size_tab_height=66dp` 是保留资源，不宣称当前主壳使用它。

### 4.3 间距与层级

遵循 4dp 网格，优先现有资源：组内 `captain_space_inline=8dp`，卡片内及间隔 16dp，页面左右 20dp，模块间 24dp，大分组 32dp。系统安全区与既有定位资源按容器语义保留，不为了网格修改内容协议。

普通卡片不加装饰性描边和阴影；导航容器当前 elevation 为 2dp。浮层仅在需要表达覆盖关系时使用既有高度角色，不为所有控件增加悬浮感。

## 5. 状态、主题与专用表现

- 默认、按压、键盘焦点和禁用必须可辨识：主按钮在品牌 700/800 间切换；次按钮在品牌 100/200 间切换；禁用复用中性色与文字 selector。辅助操作使用系统状态层。
- 加载状态必须提供可理解的进度或文字，按当前功能的 busy 状态控制重复操作；不得在视觉层再造业务状态机或改变失败重试契约。
- 空态、错误、不可用状态应有说明和原有可执行入口；不得因单项布局数据不可用让整页崩溃，也不得借样式改动增加过滤、排序或校验。
- 首版固定浅色：`CaptainApplication.onCreate` 选择 `AppCompatDelegate.MODE_NIGHT_NO`，宿主保留 `Theme.AppCompat.Light`；系统夜间模式不能作为启用全局深色的入口。运行时不提供夜间色板，旧草案仅保留在 Git 历史，避免平台原生 Activity 绕过 AppCompat 后解析暗色资源；API 29 起显式关闭 Force Dark。
- 系统栏兼容 API 21：默认深色系统栏配白图标；`values-v23` 起状态栏采用浅底深图标，`values-v27` 起导航栏采用浅底深图标（XML 主题属性 `windowLightNavigationBar` 自 API 27 提供）。`colorBackgroundFloating` 仅在 API 23 及以上主题中配置；密码与键盘外围使用 API 21 可解析的普通背景属性。各版本 `AppTheme` 仅覆盖系统栏和受 API 限制的表面属性，共用项继承 `CaptainBaseTheme`；媒体预览在页面中显式设置黑底白图标，继续优先。
- 计时器昼夜独立由天气 `isDay()` 或时间驱动，使用 `timer_colors.xml` 的具名颜色；不改为系统主题，不删除昼夜分支。
- 二维码、棋盘、自绘计时、媒体和网页遵循第 1 节的专用内容边界。隐私和密码弹层先保护可读性、最小点击区和现有授权含义。

## 6. 验收与证据

新增或变更页面先检查共享 token/样式是否足够，再检查全部改动 diff 的必要性。静态检查应核对资源引用、主题角色映射、字号单位和最小触控尺寸；构建与相关业务测试另行记录。

视觉验收需要覆盖可达页面、空态、错误态、长中文、大字体、窄屏、键盘及系统安全区；语音手势、录音收尾、候选编辑和保存失败还需要对应交互证据。编译、XML 解析和单测不能代替设备呈现。

**本文更新只证明规范与当前资源和代码经过静态对照；不声明设备视觉、真实离线识别、飞书接收或全 App 运行验收已通过。**
