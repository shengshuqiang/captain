# 2026-03-28 船长App水果色视觉Token规范

## 1. 文档目标

本文档用于沉淀船长 App 主壳层 UI 的视觉 token，作为后续需求开发、设计评审、Code Review 和回归验收的统一依据。

本规范解决 4 类问题：

1. 后续页面继续随意写颜色、字号、圆角、间距，导致风格重新发散
2. “年轻化、水果感、女生友好”停留在抽象描述，无法转换为代码约束
3. 新需求进来时不知道该复用什么，只能临时发明新样式
4. 方案通过后逐步变形、劣化、回退到旧工具页风格

本规范与以下文档配套使用：

- [2026-03-28-船长App主壳层UI视觉重构技术方案.md](/Users/shengshuqiang/dream/captain/docs/2026-03-28-船长App主壳层UI视觉重构技术方案.md)

## 2. 使用原则

### 2.1 语义优先

所有视觉资源必须按“语义”使用，而不是按“看着顺眼”使用。

正确做法：

- 品牌主按钮使用 `brand_primary`
- 页面背景使用 `surface_page`
- 白卡片使用 `surface_card`
- 标题使用 `text_primary`

错误做法：

- 某个页面觉得粉色更好看，就直接写一个新的粉色 hex
- 某个功能想更醒目，就把说明文字也改成品牌主色
- 某个卡片想更特别，就私自使用新的圆角和间距

### 2.2 复用优先

新需求新增样式前，必须先按以下顺序判断：

1. 是否已有现成 token 可复用
2. 是否已有现成组件样式可复用
3. 是否只是当前页面的局部情绪需求，而非新语义
4. 只有前三项都不成立时，才允许新增 token

### 2.3 轻品牌，不幼态

本次视觉 token 的目标是“清爽果感效率工具”，不是“甜妹社区产品”。

允许：

- 清透水果色
- 柔和圆角
- 轻渐变
- 浅色氛围区

禁止：

- 高饱和粉色全屏铺满
- 多色混搭导致糖果感过重
- 大量装饰性阴影和发光
- 为了可爱牺牲清晰度

## 3. 颜色 Token

### 3.1 品牌色

| Token | 值 | 用途 | 禁止场景 |
| --- | --- | --- | --- |
| `brand_primary` | `#FF8A8F` | 主按钮、Tab 选中态、品牌强调 | 长段正文、错误信息 |
| `brand_accent` | `#FFB56B` | 渐变终点、高光标签、轻提示点缀 | 大面积背景主色 |
| `brand_support_success` | `#78C98C` | 成功标签、完成状态、正向反馈 | 与错误或警示混用 |

### 3.2 页面与容器色

| Token | 值 | 用途 | 说明 |
| --- | --- | --- | --- |
| `surface_page` | `#FFF8F6` | 页面主背景 | 所有主壳层页面默认背景 |
| `surface_hero` | `#FFE7E3` | 首页欢迎区、顶部氛围区 | 仅用于浅氛围，不做正文承载底色 |
| `surface_card` | `#FFFFFF` | 功能卡片、列表卡片、白底容器 | 最常用容器底色 |
| `surface_card_soft` | `#FFFDFC` | 轻奶白卡片 | 用于与纯白卡片拉开轻层次 |

### 3.3 文字色

| Token | 值 | 用途 | 说明 |
| --- | --- | --- | --- |
| `text_primary` | `#2A2233` | 页面标题、卡片标题、重点信息 | 一级文字统一使用 |
| `text_secondary` | `#6D6678` | 说明、描述、次级信息 | 二级文字统一使用 |
| `text_tertiary` | `#A7A1AE` | 占位、弱提示、非关键说明 | 禁止用于主操作或核心信息 |
| `text_on_brand` | `#FFFFFF` | 品牌色按钮上的文字 | 用于主 CTA 文本 |

### 3.4 反馈与边框色

| Token | 值 | 用途 |
| --- | --- | --- |
| `border_soft` | `#F1E6E3` | 卡片边框、浅分割线 |
| `feedback_error` | `#E45B5B` | 错误态、失败态 |
| `feedback_warning` | `#E8A044` | 警示态、注意提示 |
| `feedback_success` | `#49A96A` | 完成态、成功提示 |

### 3.5 颜色使用规则

1. `brand_primary` 不直接用于长段正文。
2. `surface_hero` 只用于欢迎区、氛围区，不用于主内容大区承载。
3. 弱提示文字必须搭配非关键内容，且对比度不得低于可读底线。
4. 一个页面中品牌强色块不超过 2 块，避免情绪噪声过多。
5. 任何新颜色引入都必须先说明对应语义，而不是先描述审美。

### 3.6 对比度约束

| 规则 | 最低要求 |
| --- | --- |
| 一级正文 vs 背景 | `4.5:1` |
| 按钮文字 vs 按钮底色 | `4.5:1` |
| 大标题 vs 背景 | `3:1` |
| 弱提示文字 | 仅限非关键说明，且必须能稳定识别 |

### 3.7 Android 资源命名建议

建议在 `colors.xml` 中采用以下命名：

```xml

<color name="captain_surface_page">#FFF8F6</color>
<color name="captain_surface_hero">#FFE7E3</color>
<color name="captain_surface_card">#FFFFFF</color>
<color name="captain_surface_card_soft">#FFFDFC</color>
<color name="captain_text_primary">#2A2233</color>
<color name="captain_text_secondary">#6D6678</color>
<color name="captain_text_tertiary">#A7A1AE</color>
<color name="captain_text_on_brand">#FFFFFF</color>
<color name="captain_border_soft">#F1E6E3</color>
```

## 4. 字号 Token

### 4.1 字号层级

| Token | 值 | 用途 |
| --- | --- | --- |
| `text_hero` | `22sp` | 首页品牌标题、欢迎区主标题 |
| `text_page_title` | `20sp` | 页面标题、区块主标题 |
| `text_card_title` | `16sp` | 卡片标题、列表项主标题 |
| `text_body` | `14sp` | 正文、常规说明 |
| `text_caption` | `12sp` | 标签、版本号、次级提示 |
| `text_tab` | `12sp` | 底部导航标题 |

### 4.2 字重建议

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `weight_semibold` | `600` | Hero、页面标题、卡片标题 |
| `weight_medium` | `500` | Tab、badge、次强调 |
| `weight_regular` | `400` | 正文、说明、辅助 |

### 4.3 字号使用规则

1. 一页内不要出现多个接近但不同的标题字号。
2. 不允许使用 `dp/dip` 定义文字大小。
3. 不允许为挤内容而把主信息字号往下压一级。
4. 文本层级通过字号、字重、颜色共同实现，不靠单一粗体堆叠。

### 4.4 Android 资源命名建议

建议在 `dimens.xml` 中采用以下命名：

```xml
<dimen name="captain_text_hero">22sp</dimen>
<dimen name="captain_text_page_title">20sp</dimen>
<dimen name="captain_text_card_title">16sp</dimen>
<dimen name="captain_text_body">14sp</dimen>
<dimen name="captain_text_caption">12sp</dimen>
<dimen name="captain_text_tab">12sp</dimen>
```

## 5. 圆角 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `radius_card_large` | `20dp` | 首页主卡片、大容器 |
| `radius_card` | `16dp` | 常规卡片、列表卡片 |
| `radius_button` | `14dp` | 主按钮、次按钮 |
| `radius_badge` | `12dp` | badge、轻标签 |
| `radius_avatar` | `24dp` 或圆形 | 品牌头像、个人头像 |

规则：

1. 新页面优先复用 `radius_card` 和 `radius_card_large`。
2. 不允许页面私自出现 6dp、9dp、13dp 这种无语义圆角。
3. 圆角只能增强柔和度，不能替代结构层级。

## 6. 间距 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `space_page_horizontal` | `20dp` | 页面左右边距 |
| `space_hero_inner` | `24dp` | 欢迎区内边距 |
| `space_card_inner` | `16dp` | 卡片内边距 |
| `space_block` | `24dp` | 模块间距 |
| `space_card_gap` | `12dp` | 卡片之间间距 |
| `space_inline` | `8dp` | 行内元素间距 |

规则：

1. 模块间距不能小于卡片间距。
2. 页面整体默认要比旧版更松，不允许为了塞内容回退到工具墙密度。
3. 新需求如果需要更紧凑布局，必须先说明是业务强约束还是页面偷懒。

## 7. 尺寸底线 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `size_tab_height` | `66dp` | 底部 Tab 目标高度 |
| `size_tab_icon` | `24dp` | Tab 图标 |
| `size_button_height` | `44dp` | 主按钮最小高度 |
| `size_list_item_height` | `56dp` | 列表项最小高度 |
| `size_avatar` | `72dp` | 顶部品牌头像默认尺寸 |

规则：

1. 不允许通过缩小按钮高度换取视觉“精致”。
2. 列表项高度低于 `56dp` 需明确例外说明。
3. 点击目标必须优先满足可用性，再谈轻盈感。
4. 底部 Tab 高度允许在 `64dp` - `68dp` 间微调，但资源默认值统一为 `66dp`。
5. 顶部品牌头像仅在需要强化品牌感时才放大到 `80dp`，默认值保持 `72dp`。

## 8. 组件语义规范

### 8.1 首页欢迎区

| 属性 | 规范 |
| --- | --- |
| 背景 | `surface_hero` 或其轻渐变 |
| 主标题 | `text_hero + text_primary + semibold` |
| 副标题 | `text_caption` 或 `text_body`，使用 `text_secondary` |
| 装饰 | 轻量，禁止复杂插画堆砌 |

### 8.2 功能卡片

| 属性 | 规范 |
| --- | --- |
| 背景 | `surface_card` 或 `surface_card_soft` |
| 圆角 | `radius_card_large` |
| 标题 | `text_card_title + text_primary` |
| 说明 | `text_body` 或 `text_caption + text_secondary` |
| 标签 | `radius_badge + brand_support_success` 或浅底轻标签 |

### 8.3 列表卡片

| 属性 | 规范 |
| --- | --- |
| 背景 | `surface_card` |
| 圆角 | `radius_card` |
| 主文案 | `text_card_title` 或 `text_body` |
| 右箭头 | 低噪声中性色 |

### 8.4 主按钮

| 属性 | 规范 |
| --- | --- |
| 背景 | `brand_primary` 或品牌渐变 |
| 文字 | `text_on_brand` |
| 圆角 | `radius_button` |
| 高度 | 不低于 `44dp` |

### 8.5 底部 Tab

| 属性 | 规范 |
| --- | --- |
| 图标尺寸 | `24dp` |
| 文案 | `text_tab` |
| 未选中态 | `text_tertiary` 或中性弱色 |
| 选中态 | `brand_primary` + 轻底托 |

## 9. 文案语气 Token

### 9.1 文案分类

| 类型 | 用途 | 风格 |
| --- | --- | --- |
| `copy_brand_light` | 首页欢迎区、我的页简介、空态引导 | 轻松、亲和、有活力 |
| `copy_function_clear` | 保存、删除、权限、隐私、操作结果 | 准确、清晰、功能导向 |
| `copy_label_short` | badge、轻标签、状态标记 | 短、准、可扫读 |

### 9.2 文案边界

1. 品牌轻文案不能替代功能说明。
2. 错误、权限、隐私、删除、保存结果必须用功能型文案。
3. 不允许把口号写进高风险操作弹窗。

## 10. 新增需求接入规则

后续任何 UI 需求进入时，必须先回答以下问题：

1. 有没有复用现有颜色 token？
2. 有没有复用现有字号和间距 token？
3. 新模块属于欢迎区、功能区、列表区还是例外区？
4. 文案属于品牌轻文案还是严肃功能文案？
5. 有没有引入新的无语义特例样式？

若答案存在风险项，则该需求不能直接进入开发。

## 11. Code Review 最低检查项

涉及主壳层 UI 的改动，CR 至少检查以下内容：

- 是否新增了硬编码颜色
- 是否新增了 `dp/dip` 文本尺寸
- 是否压缩了按钮或列表项高度
- 是否出现新的私有圆角、私有间距
- 是否把品牌轻文案误用到严肃场景
- 是否新增无依据的推荐区或装饰区
- 是否破坏既有页面骨架

## 12. 禁止事项

以下做法默认禁止：

- 直接在布局文件里写新的品牌粉、品牌橙、品牌绿
- 为了“更可爱”增加不必要的插画、发光、描边和阴影
- 为了放更多内容而整体缩小字号
- 让首页回退成九宫格工具墙
- 让“我的”页重新退化为长说明 + 大空白 + 一条列表
- 把一页做得很甜，另一页做得很旧

## 13. 建议的资源落地文件

建议后续优先在以下文件内落地：

- `captain/src/main/res/values/colors.xml`
- `captain/src/main/res/values/dimens.xml`
- `captain/src/main/res/values/styles.xml`
- `captain/src/main/res/drawable/` 下的按钮、卡片、badge 背景资源

## 14. 总结

这份 token 规范的目标，不是让界面“统一成一种颜色”，而是让船长 App 的年轻化、水果感、轻盈感变成可复用、可检查、可维护的系统资产。后续需求只要还遵守这套 token，产品就不容易重新变回老旧、散乱、粗糙的工具页。
