# 2026-03-28 船长App主壳层UI视觉重构技术方案

## 1. 文档目标

本文档用于指导船长 App 主壳层 UI 的重构，覆盖以下范围：

- 顶部标题栏
- 底部 Tab 导航
- 首页功能入口区
- “我的”页面
- 全局颜色、字号、间距、圆角、组件语义等视觉基础规范

本次方案不再以“旧版工具 App 整理升级”为目标，而是以“年轻化品牌重塑”为目标，要求整体视觉达到以下方向：

- 新潮但不过度花哨
- 简洁大方但不冷淡
- 适合年轻人，尤其是女生
- 具备轻盈、清爽、精致、有活力的观感
- 优先采用水果感配色，但保持产品专业度和长期可维护性

## 2. 设计重心

### 2.1 目标用户感知

用户打开船长 App 的第一感受，不应该是“一个老派工具集合”，而应该是：

- 好看
- 轻松
- 干净
- 有记忆点
- 愿意停留和继续探索

对于年轻用户，尤其是女性用户，界面除了“能用”，还要提供明确的情绪价值：

- 颜色不压抑
- 信息不生硬
- 组件不粗糙
- 排版有呼吸感
- 风格统一，有被认真设计过的感觉

### 2.1.1 用户分层与设计边界

为了避免“年轻化”被执行成泛化审美口号，本方案明确以下用户分层：

| 用户层级 | 定义 | 设计优先级 | 设计要求 |
| --- | --- | --- | --- |
| 主用户 | 18-30 岁的年轻用户，偏高频手机使用者，接受轻品牌感界面 | 最高 | 首屏要轻松、顺眼、有活力，不要老旧工具感 |
| 次用户 | 对效率工具有明确需求的泛用户，包括男性用户和轻工具用户 | 高 | 页面不能过甜、不能幼态，仍要保留清晰和效率 |
| 保底用户 | 仅因功能需求进入页面的非审美驱动用户 | 中 | 核心流程必须稳定、可读、可点击，不因风格牺牲可用性 |

本方案的风格边界如下：

- 允许：清爽果色、轻渐变、柔和圆角、轻情绪文案
- 不允许：大面积高饱和铺满、幼态插画、过甜粉感、低对比浅字、过强装饰感
- 风格目标：偏“清新果感效率工具”，不是“少女社区 App”，也不是“企业后台”

### 2.2 产品气质定位

船长 App 应从“高效率个人工具箱”升级为“轻盈、有活力、高颜值的效率助手”。

这个定位包含 4 层含义：

1. 仍然是工具产品，但不能做成后台系统气质。
2. 仍然强调效率，但不能牺牲亲和感和审美体验。
3. 仍然要可信赖，但不能只剩“稳重”和“克制”。
4. 页面应该有品牌氛围，而不是只有功能入口。

### 2.3 设计关键词

本次方案统一采用以下关键词：

- 清爽
- 轻盈
- 明快
- 精致
- 亲和
- 有活力
- 专业但不冷

禁止继续沿用以下过旧关键词主导整体设计：

- 过度稳重
- 过度商务
- 过度理工
- 过度系统感

## 4. 新的视觉方向

### 4.1 整体策略

视觉上采用“水果感色彩 + 大面积留白 + 轻卡片 + 软高光细节”的路线。

这个方向的目标不是把 App 做成“甜品 UI”，而是让界面在保持清晰和效率的前提下，拥有以下特征：

- 看起来轻，不沉
- 看起来新，不旧
- 看起来有情绪，但不幼稚
- 看起来精致，但不复杂

### 4.2 年轻化表达原则

本次方案增加以下品牌表达原则：

1. 颜色要有愉悦感  
   不使用压抑深色做主视觉，不用强工业感蓝灰体系统治页面。

2. 组件要有柔和度  
   卡片、标签、导航选中态要有轻柔的包裹感，而不是硬边线框感。

3. 首屏要有氛围  
   首页不能只有功能，要有欢迎区、品牌语气和视觉记忆点。

4. 信息要有节奏  
   主标题、说明文案、状态标签和入口卡片之间要有明显层级，不做同强度堆叠。

5. 简洁不是无聊  
   简洁强调的是去掉噪声，不是去掉情绪与气质。

## 5. 色彩系统方案

### 5.1 总体思路

本次方案采用“水果色主品牌 + 中性色承载信息 + 局部奶白衬底”的结构。

原则如下：

- 主壳层允许水果感颜色参与品牌表达
- 页面主体仍保持足够留白，避免大面积高饱和
- 颜色主要负责情绪引导和状态强化，不应干扰信息阅读
- 不采用深海蓝作为主壳层主色

### 5.2 推荐主方案

推荐采用“蜜桃西柚 + 青提薄荷”双轴色系：

| 类型 | 建议值 | 用途 |
| --- | --- | --- |
| 品牌主色 | `#FF8A8F` | 品牌识别、选中态、重点按钮 |
| 品牌强调色 | `#FFB56B` | 高光、主按钮渐变终点、活力点缀 |
| 辅助活力色 | `#78C98C` | 成功态、轻标签、辅助状态 |
| 页面背景 | `#FFF8F6` | 主页面底色 |
| 顶部氛围底色 | `#FFE7E3` | 首页顶部欢迎区、浅色渐变区 |
| 卡片底色 | `#FFFFFF` | 卡片、功能块、列表容器 |
| 一级文字 | `#2A2233` | 标题、重点信息 |
| 二级文字 | `#6D6678` | 说明、描述、辅助信息 |
| 弱化文字 | `#A7A1AE` | 占位、提示、弱状态 |
| 分割线 | `#F1E6E3` | 边框、轻分割 |
| 错误色 | `#E45B5B` | 错误态 |

### 5.3 配色约束

- 不再使用荧光绿作为底部导航选中态。
- 不再使用 `#3F51B5 + #FF4081` 这类旧模板配色作为主壳层基线。
- 不允许页面大面积同时使用 3 个以上高饱和色。
- 颜色必须抽象成语义 token，禁止大面积硬编码。

### 5.3.1 可访问性与对比度约束

为避免水果色方案落地后出现“发虚、发灰、看不清”的问题，增加以下硬性约束：

| 场景 | 规则 |
| --- | --- |
| 一级正文文字 vs 背景 | 对比度不低于 `4.5:1` |
| 大标题文字 vs 背景 | 对比度不低于 `3:1` |
| 按钮文字 vs 按钮底色 | 对比度不低于 `4.5:1` |
| 弱提示文字 | 仅允许用于非关键说明，不可用于主操作或重要状态 |
| 选中态浅底托 | 必须搭配足够深的图标或文字色，禁止浅底托叠浅字 |

实现规则：

- 水果色优先用于底托、标签、按钮背景、氛围区，不直接用于长段正文。
- 正文层文字统一落在深色文字 token，不允许把一级正文换成品牌浅色。
- 页面上所有主操作按钮、选中态标签、重点数字都要做一次对比度检查。

### 5.3.2 颜色语义映射

为保证后续需求持续一致，颜色必须通过语义 token 使用，不允许按页面心情自由选色。

| 语义 token | 默认值 | 适用场景 |
| --- | --- | --- |
| `brand_primary` | `#FF8A8F` | 品牌识别、主选中态、主 CTA |
| `brand_accent` | `#FFB56B` | 高光、强调标签、渐变终点 |
| `brand_support_success` | `#78C98C` | 成功态、完成标签 |
| `surface_page` | `#FFF8F6` | 页面底色 |
| `surface_hero` | `#FFE7E3` | 顶部欢迎区、氛围区 |
| `surface_card` | `#FFFFFF` | 白卡、列表项卡片 |
| `text_primary` | `#2A2233` | 标题、重点文字 |
| `text_secondary` | `#6D6678` | 描述、说明 |
| `text_tertiary` | `#A7A1AE` | 占位、弱提示 |
| `border_soft` | `#F1E6E3` | 卡片描边、细分割 |
| `feedback_error` | `#E45B5B` | 错误态 |

要求：

- 代码实现时优先新增颜色资源而不是直接写 hex。
- 新需求新增颜色前，必须先判断是否能复用现有 token。
- 若必须新增 token，必须说明语义归属和替代失败原因。

### 5.4 备用方案

若后续验证发现主色偏甜，可切换成更清爽的“青提柠檬”方案：

- 主品牌色：`#8BCF7B`
- 强调色：`#F6C94C`
- 页面背景：`#FBFDF7`
- 顶部氛围底色：`#EEF9E9`

该方案更中性，但品牌记忆点会略弱于“蜜桃西柚”。

## 6. 字号、圆角与间距规范

### 6.1 字号层级

统一采用 `sp`：

| 层级 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| Hero 标题 | `22sp` | `600` | 首页主标题、品牌标题 |
| 页面标题 | `20sp` | `600` | 顶栏标题、区块标题 |
| 卡片标题 | `16sp` | `600` | 功能卡标题、列表主标题 |
| 正文 | `14sp` | `400` | 常规说明文案 |
| 辅助文字 | `12sp` | `400` | 版本号、描述、标签 |
| Tab 文案 | `11sp`-`12sp` | `500` | 底部导航标题 |

约束：

- 统一用 `sp`，禁止再用 `dp/dip` 定义文本。
- 不允许同一语义层级出现多个相近字号。
- 文本重点通过字号、字重、颜色三者共同控制，不依赖单一手段。

### 6.2 圆角规范

建议统一如下：

| 类型 | 值 |
| --- | --- |
| 大卡片圆角 | `20dp` |
| 普通卡片圆角 | `16dp` |
| 小标签圆角 | `12dp` |
| 按钮圆角 | `14dp` |
| 头像圆角 | 圆形或 `24dp` 超大圆角 |

原则：

- 整体要柔和，但不能软塌。
- 圆角体现年轻感和亲和感，但不能夸张到幼态。

### 6.3 间距规范

| 类型 | 值 |
| --- | --- |
| 页面左右边距 | `20dp` |
| 顶部氛围区内边距 | `24dp` |
| 卡片内边距 | `16dp` |
| 卡片间距 | `12dp` |
| 模块间距 | `24dp` |
| 小元素间距 | `8dp` |

原则：

- 页面整体要比当前版本更松，更有空气感。
- 年轻化不等于堆满装饰，核心是留白质量提升。

### 6.4 组件规格下限

为了防止后续需求“越做越挤、越做越碎”，增加组件规格底线：

| 组件 | 约束 |
| --- | --- |
| 底部 Tab 高度 | `64dp` - `68dp` |
| Tab 图标 | `24dp` |
| 主按钮高度 | 不低于 `44dp` |
| 列表项高度 | 不低于 `56dp` |
| 首页卡片标题 | 最多 1 行 |
| 首页卡片说明 | 最多 2 行 |
| 页面首屏主标题 | 最多 1 行 |
| 页面首屏副标题 | 最多 2 行 |

禁止行为：

- 为塞更多信息随意缩小字号
- 用更小的圆角和更紧的间距回退到旧工具页观感
- 用局部 magic number 压缩页面呼吸感

## 7. 页面级重构方案

### 7.1 顶部标题栏

#### 目标

把顶栏从“系统工具栏”升级为“品牌欢迎区入口”。

#### 方案

- 首页顶部不再使用整块纯色 `Toolbar` 作为主视觉。
- 顶部改为浅水果色氛围区，允许轻渐变。
- 标题使用品牌语气，如“船长”或“今天想让船长帮你处理点什么？”
- 副标题使用一行轻说明文案，传达轻松感和效率感。
- 右上角保留 1 个轻操作入口，例如设置、反馈或更多。
- 首屏视觉重心从“导航条”转移到“欢迎区 + 功能区”。

#### 视觉建议

- 背景：`#FFE7E3 -> #FFF8F6` 轻渐变
- 主标题：`22sp` 半粗体
- 副标题：`12sp` 或 `13sp`
- 可加入小型品牌图形点缀，但不建议复杂插画

### 7.2 底部 Tab 导航

#### 目标

把当前偏控件演示风格的底部导航，改造成柔和、轻巧、有品牌辨识度的主导航。

#### 方案

- 保留 `首页`、`我的` 两个一级入口。
- 导航整体高度控制在 `64dp` 到 `68dp`。
- 图标建议采用 `24dp` 统一视觉规格。
- 未选中态使用低饱和灰紫色。
- 选中态采用蜜桃色或蜜桃到橙色的轻高光表达。
- 选中项建议有浅底托，而不是只改图标颜色。
- 动效保持轻微，不做夸张滑块或过重转场。

#### 技术建议

- 短期：保留 `NavigationTabBar`，但仅保留最基础能力，收敛高度、颜色、标题和字体。
- 中期：替换为更轻的自定义导航容器，避免第三方控件视觉上限过低。

#### 实现边界

为了避免“以为调参数就能达到方案效果”，明确分层如下：

| 层级 | 可实现内容 | 方式 |
| --- | --- | --- |
| 低成本可达 | 颜色、标题、字号、高度、图标尺寸收敛 | 保留现有控件，改资源和参数 |
| 中成本可达 | 选中底托、导航背景、轻阴影、结构优化 | 局部自定义布局包裹或替换部分实现 |
| 高成本才可达 | 高质量品牌导航、细腻状态动效、完整统一图标语言 | 替换 `NavigationTabBar`，重做底部导航容器 |

结论：

- 若本期不替换底部导航控件，只能做到“明显变好”，不能承诺“完全达到最终品牌效果”。

### 7.3 首页功能入口区

#### 目标

把首页从“九宫格工具页”升级成“有氛围、有主次、有品牌感的轻工具首页”。

#### 推荐结构

### 7.4 “我的”页

#### 目标

把“我的”页从说明页升级成“轻品牌个人页”，兼顾信息清晰和情绪价值。

#### 推荐结构

1. 顶部品牌卡
   - 头像或品牌图标
   - 应用名
   - 版本号 badge

2. 简介卡
   - 一句产品介绍
   - 一句轻联系文案

3. 功能列表卡
   - 隐私政策
   - 版本说明
   - 联系作者
   - 意见反馈

#### 视觉建议

- 顶部区域使用淡水果色底板，不直接裸露纯白信息堆叠
- 头像缩至 `72dp` 或 `80dp`
- 版本号使用圆角 badge 展示
- 简介文案不要写成长段说明，控制在两句之内
- 列表项做成分组卡片，避免“整页一条长列表”的粗糙感

#### 文案语气建议

- 产品介绍示例：
  - 船长，帮你把麻烦的小事处理得更轻松。
  - 一个轻盈、好用、顺手的效率小帮手。

- 联系语气示例：
  - 有建议，欢迎来找我聊聊。
  - 一起把这只船，开得更顺一点。

#### 文案使用边界

为了避免“轻文案”削弱工具产品可信度，增加以下规则：

| 文案类型 | 允许场景 | 禁止场景 |
| --- | --- | --- |
| 品牌轻文案 | 首页欢迎区、我的页简介、空态引导 | 错误提示、权限弹窗、隐私条款、保存结果 |
| 严肃功能文案 | 保存、删除、权限、隐私、失败提示 | 不允许被品牌口号替代 |
| 列表项文案 | 以动作和结果为主，简洁直给 | 不允许过于情绪化、模糊化 |

执行要求：

- 隐私、错误、权限、删除、保存等高风险场景，必须优先使用清晰、明确、功能导向文案。
- 品牌语气文案仅作为氛围增强，不能替代功能说明。

#### 技术建议

- 外层改为可滚动容器
- 列表项从 Java 动态创建迁移到 XML item layout
- 页面按卡片分组组织，减少裸露文本堆叠

## 8. 技术落地策略

| 层级 | 内容 | 目标 |

要求：

- 任何新需求先判断落在哪一层，再决定实现方式。
- L1 未统一前，禁止在页面里大量追加局部样式。
- L2 未稳定前，L3 不应过度提前。

## 9. 验收标准

### 9.1 视觉方向验收

- 界面第一眼必须明显年轻于当前版本
- 页面不再呈现旧 Android 工具页气质
- 欢迎区、功能区、个人页风格一致，不出现一处甜一处旧的割裂感

### 9.2 用户感知验收

- 年轻用户能感知到页面更轻、更新、更精致
- 女性用户不会感觉页面冷硬、粗糙、理工味重
- 整体颜色有活力但不刺眼

### 9.3 结构与信息验收

- 顶栏、底部导航、首页、“我的”页形成统一语言
- 页面主次关系明确
- 文案、颜色、组件不再互相打架

### 9.3.1 可检查指标

为避免验收停留在主观感受，增加以下可检查项：

| 类别 | 指标 |
| --- | --- |
| 字号 | 页面内不存在 `dp/dip` 定义文字大小 |
| 颜色 | 页面主壳层不新增未登记的硬编码品牌色 |
| 顶栏 | 首页欢迎区标题不超过 1 行，副标题不超过 2 行 |
| 首页卡片 | 卡片标题不超过 1 行，说明不超过 2 行 |
| 底部导航 | 高度维持 `64dp` - `68dp`，图标维持 `24dp` |
| 列表项 | 高度不低于 `56dp` |
| 主按钮 | 高度不低于 `44dp`，文字清晰可读 |
| 文案 | 品牌轻文案未出现在权限、隐私、错误、删除等严肃场景 |
| 推荐区 | 无真实推荐依据时不展示 |

### 9.4 技术可维护性验收

- 颜色、字号、圆角、间距尽量资源化
- 新页面能复用现有 token 和卡片规范
- 样式不依赖大量布局层硬编码

### 9.5 设计不变形验收

- 新需求接入后，未引入新的无语义颜色资源
- 新页面未回退到“标题一行、列表一长串、纯功能堆叠”的旧样式
- 页面新增模块仍遵守“欢迎区/功能区/个人页卡片区”的结构原则
- 新功能若破坏现有视觉标准，必须在需求文档中显式说明例外原因

## 10. 长期防劣化机制

### 10.1 设计资产治理

为确保后续需求持续按本次标准落地，必须沉淀以下资产：

1. 颜色 token 表  
   所有品牌色、语义色、状态色统一登记。

2. 字号与间距 token 表  
   所有壳层页面统一复用。

3. 页面骨架模板  
   首页模板、我的页模板、列表页模板。

4. 文案语气规范  
   品牌文案和严肃功能文案分别管理。

5. 组件白名单  
   主按钮、次按钮、卡片、badge、Tab、列表项使用统一样式。

### 10.2 需求接入门禁

后续任何 UI 需求进入时，必须先过以下 5 个问题：

1. 新需求是否复用了已有颜色 token？
2. 新需求是否复用了既有卡片或列表结构？
3. 新文案属于品牌文案还是严肃功能文案？
4. 新模块是否破坏首页或我的页既定骨架？
5. 是否新增了一个未来难以统一维护的特例样式？

若其中任意一项答案为“是风险项”，则必须在方案评审时说明，不允许直接落代码。

### 10.3 Code Review 审查清单

后续涉及壳层 UI 的改动，CR 时至少检查：

- 是否新增了硬编码颜色
- 是否新增了 `dp/dip` 文本尺寸
- 是否压缩了点击区域或列表项高度
- 是否在首页随意增加新块导致层级膨胀
- 是否把品牌轻文案误用到严肃场景
- 是否新增了只在单页存在的特殊圆角、阴影、间距

### 10.4 例外管理机制

允许有例外，但必须受控：

- 例外只能因业务强约束出现，不能因“临时好看”出现
- 例外必须在需求文档中说明原因、影响范围、回收计划
- 例外默认是临时方案，不自动升级为新标准

### 10.5 防止持续劣化的核心原则

后续页面最容易变形的方式有 4 种：

1. 颜色越来越多
2. 模块越来越碎
3. 文案越来越花
4. 控件越来越不统一

对应治理原则：

- 颜色只增语义，不增情绪噪声
- 模块只因信息结构增加，不因“想丰富页面”增加
- 文案只在品牌位有情绪，在功能位保持明确
- 控件只扩展复用，不做页面级私有风格

## 11. 风险与注意事项

- 水果色系要控制“清爽”而不是“过甜”，避免显得幼态。
- 年轻化不等于大面积渐变和过度装饰，核心仍是清晰和节奏。
- 若保留旧版第三方底部导航控件，只调参数可能只能做到“比以前顺眼”，未必能达到真正高质量效果。
- 首页若后续继续新增功能，需要确保卡片体系可扩展，不要再次回退成杂乱工具墙。
- 若没有 token、模板、CR 门禁三件套，后续每个需求都可能把当前标准重新打散。
