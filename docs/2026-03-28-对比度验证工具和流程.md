# 2026-03-28 对比度验证工具和流程

## 1. 文档目标

本文档提供完整的颜色对比度验证工具、流程和预验证表，确保船长 App 的视觉 token 符合 WCAG 可访问性标准。

## 2. 对比度标准

根据 WCAG 2.1 标准：

| 场景 | 最低对比度 | 标准等级 |
|------|-----------|---------|
| 一级正文文字 vs 背景 | 4.5:1 | AA |
| 大标题文字 vs 背景 | 3:1 | AA |
| 按钮文字 vs 按钮底色 | 4.5:1 | AA |
| 图标 vs 背景 | 3:1 | AA |

## 5. 开发流程中的验证步骤

### 5.1 设计阶段

1. 使用 WebAIM Contrast Checker 验证所有文字颜色组合
2. 记录对比度结果到设计文档
3. 对于不通过的组合，调整颜色或限制使用场景

### 5.2 开发阶段

1. 使用 token 而不是硬编码颜色
2. 参考本文档的预验证表
3. 对于新增颜色组合，必须先验证对比度

### 5.3 Code Review 阶段

检查清单：
- [ ] 是否使用了禁止组合？
- [ ] 一级正文是否使用 `text_primary`？
- [ ] 弱提示文字是否仅用于非关键信息？
- [ ] 按钮文字对比度是否 ≥ 4.5:1？

### 5.4 测试阶段

1. 在真机上查看实际效果
2. 在不同光线环境下测试可读性
3. 使用 Android Accessibility Scanner 扫描

## 6. 自动化验证脚本

### 6.1 Python 脚本

```python
#!/usr/bin/env python3
"""
船长 App 颜色对比度验证脚本
使用方法: python check_contrast.py
"""

def hex_to_rgb(hex_color):
    """将 hex 颜色转换为 RGB"""
    hex_color = hex_color.lstrip('#')
    return tuple(int(hex_color[i:i+2], 16) for i in (0, 2, 4))

def relative_luminance(rgb):
    """计算相对亮度"""
    r, g, b = [x / 255.0 for x in rgb]
    r = r / 12.92 if r <= 0.03928 else ((r + 0.055) / 1.055) ** 2.4
    g = g / 12.92 if g <= 0.03928 else ((g + 0.055) / 1.055) ** 2.4
    b = b / 12.92 if b <= 0.03928 else ((b + 0.055) / 1.055) ** 2.4
    return 0.2126 * r + 0.7152 * g + 0.0722 * b

def contrast_ratio(color1, color2):
    """计算对比度"""
    l1 = relative_luminance(hex_to_rgb(color1))
    l2 = relative_luminance(hex_to_rgb(color2))
    lighter = max(l1, l2)
    darker = min(l1, l2)
    return (lighter + 0.05) / (darker + 0.05)

def check_wcag(ratio, level='AA', size='normal'):
    """检查是否符合 WCAG 标准"""
    if level == 'AA':
        if size == 'normal':
            return ratio >= 4.5
        else:  # large text
            return ratio >= 3.0
    return False

# 船长 App 颜色定义
colors = {
    'brand_primary': '#FF8A8F',
    'brand_accent': '#FFB56B',
    'surface_page': '#FFF8F6',
    'surface_card': '#FFFFFF',
    'text_primary': '#2A2233',
    'text_secondary': '#6D6678',
    'text_tertiary': '#A7A1AE',
    'text_on_brand': '#FFFFFF',
}

# 需要验证的组合
combinations = [
    ('text_on_brand', 'brand_primary', 'normal', '主按钮文字'),
    ('text_primary', 'surface_page', 'normal', '页面正文'),
    ('text_primary', 'surface_card', 'normal', '卡片标题'),
    ('text_secondary', 'surface_page', 'normal', '说明文字'),
    ('text_tertiary', 'surface_page', 'normal', '弱提示'),
]

print("船长 App 颜色对比度验证结果\n")
print(f"{'前景色':<20} {'背景色':<20} {'对比度':<10} {'WCAG AA':<10} {'场景'}")
print("-" * 80)

for fg_name, bg_name, size, scene in combinations:
    fg = colors[fg_name]
    bg = colors[bg_name]
    ratio = contrast_ratio(fg, bg)
    passed = check_wcag(ratio, 'AA', size)
    status = '✅ 通过' if passed else '❌ 不通过'
    print(f"{fg_name:<20} {bg_name:<20} {ratio:<10.2f} {status:<10} {scene}")
```


## 8. 常见问题

### Q1: 弱提示文字对比度不足怎么办？

**A:** `text_tertiary` 设计上就是低对比度，仅用于非关键信息（如占位符、版本号）。如果信息重要，必须使用 `text_secondary` 或 `text_primary`。

### Q2: 品牌色能否直接用于文字？

**A:** 不能。`brand_primary` 和 `brand_accent` 在浅色背景上对比度极低，只能用于：
- 按钮背景（配合白色文字）
- 图标（尺寸足够大）
- 装饰性元素（非信息承载）

### Q3: 如何提高对比度？

**方法：**
1. 加深文字颜色
2. 加深背景颜色
3. 增加文字描边（不推荐，影响美观）
4. 使用阴影（不推荐，违反设计规范）

**推荐：** 优先使用预定义的 token 组合，已经过验证。

## 9. 总结

对比度验证是确保可访问性的关键步骤。开发过程中：

1. ✅ 优先使用预验证的 token 组合
2. ✅ 新增组合必须先验证对比度
3. ✅ Code Review 时检查对比度
4. ❌ 禁止使用未验证的颜色组合
5. ❌ 禁止为了"好看"牺牲可读性

**记住：可访问性不是可选项，是必需品。**
